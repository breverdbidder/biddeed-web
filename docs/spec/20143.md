## §1 — Commerce pages

- `app/pricing/page.tsx` → `components/pricing/PricingTiers.tsx`
  - Renders the canon four tiers from a **single shared source**: `PLANS` in `components/deed-home/LandingSections.tsx` (now `export`ed, with `annualPrice`/`annualPer` fields added). This is deliberate — `scripts/canon-gate.mjs` already validates the monthly prices in that file, so the pricing page inherits the same gate instead of duplicating literal price strings that could drift. See §NEGATIVE-TEST-3 for the gate run.
  - Monthly/annual toggle. Annual prices: Investor $990, Pro $1,990, Pro Plus $3,990 — exactly the canon annual set from the issue body.
  - Report CTA banner links to `/buy-report`.
- `app/subscribe/page.tsx` → `components/subscribe/SubscribeCheckout.tsx`
  - Reads `?tier=investor|pro|proplus` (defaults to `pro`, matching the live page's default), optional `?interval=annual` (additive, for the pricing-page annual link-through) and `?ref=` (referral code, preserved from the current live behavior).
  - POSTs **exactly** `{tier, customer_email, interval}` to `/subscribe/checkout`, plus optional `referral_code`/`visitor_id` passthroughs the live Worker page already sends today (`localStorage.bd_vid`) — additive, not a contract change.
- `app/buy-report/page.tsx` → `components/buy-report/BuyReportCheckout.tsx` (replaces the old stub page, which was a disabled "Checkout integration pending certification" preview — not the real 3-step flow described in the issue)
  - Ports the live Worker's 3-step flow: county → auction → email, calling the existing `/buy-report/counties` and `/buy-report/auctions?county=` JSON endpoints (unchanged, not part of this repo).
  - Also ports the `?mca_id=&address=&county=&date=` prefill path used by property-card links from chat (fetches `/property/:id`, skips straight to checkout).
  - POSTs **exactly** `{email, county, case_number, mca_id, marketing_consent}` to `/buy-report/checkout`.

**Pending, by design (non-goal in the issue):** the Worker's proxy allow-list currently proxies exactly five path shapes to this app — `'/'`, `'/_next/*'`, three `/api/*` trees, `'/radar*'`, `'/order/success'` (see `app/layout.tsx` line ~35 comment, and confirmed live: `curl https://biddeed.ai/pricing | grep -c _next/static/css` → `0` today). `/pricing`, `/subscribe`, `/buy-report` are NOT in that list, so the live site still serves the old hand-rolled Worker HTML until the sibling lane flips it. **DO NOT flip it from here** — instruction explicit.
